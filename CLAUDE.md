# CLAUDE.md — standing instructions for Claude on this project

This repo is the EE 5113 (VLSI System Design, UTSA) two-person final project:
**Low-Precision Hardware Accelerator for Voice Keyword Recognition**. The pipeline is:
- Python: train, then quantize to INT8/INT4 (`python/`, golden model `python/quant.py`).
- Verilog: the accelerator (`rtl/kws_accel.v`, chip tops in `rtl/kws_top.v`).
- RTL Compiler + Innovus (TSMC 180 nm `tsmc18`, on `crosby3.utsarr.net`): the ASIC flow (`flow/tsmc18/`).
- Vivado on a Nexys 4 / Nexys 4 DDR / Nexys A7 (Artix-7): simulation and the board demo (`sim/`, `fpga/`).
- `alt/sergio_bram_design/` is the other version of the design (on-chip ROMs, Genus/gpdk045), kept intact.

Two students work on it from Mac, Windows and crosby3, and GitHub is how they stay in sync.

## Ground rules for changes

- `python/quant.py::int_forward` is the golden model. Any arithmetic change must be made in both it and
  `rtl/kws_accel.v`. After the change, rerun the simulation for `int8`, `int4` and `fpga`
  (`.\sim\run_sim.ps1 <target>` on Windows, `./sim/run_sim.sh <target>` on Linux); all must print
  `TEST PASSED` with 0 mismatches.
- `weights/<prec>/*` is generated by `python/export_hw.py`, `fpga/mem/*` by `python fpga/gen_fpga_mem.py`, and
  `weights/frontend.npz` by `python python/export_frontend.py`. Never hand-edit them. If `ACC_W` or `SHIFT`
  changes in `kws_params.vh`, update the parameters in `rtl/kws_top.v` and `fpga/kws_fpga_top.v` (`SHIFT` and the
  `ACC8`/`ACC4` localparams) too, and `ACC8`/`ACC4` in `tb/tb_fpga_top.v`.
- The same `rtl/kws_accel.v` is used by simulation, the ASIC flow and the FPGA. There is only one copy.
- The tsmc18 library files (`slow.lib`, `all.lef`, `gds2_innovus-2.map`) are licensed course files: they
  are copied into `flow/tsmc18/` on crosby3 and are git-ignored. **Never commit them** (the repo is public).
- Never commit tool run directories (`work/`, `fpga/work/`, `flow/tsmc18/out_*`, `*.enc.dat`, logs).
  Curated reports go into `results/<int8|int4|fpga>/`: use `flow/tsmc18/save_results.sh <prec>`; FPGA
  builds write `results/fpga/` themselves, and only when setup and hold timing are met.
- Cadence tools run only on crosby3. Claude usually runs on a laptop, so the loop is:
  1. Edit here and push.
  2. The student runs `git pull` on crosby3, then the flow in `flow/tsmc18/RUN_GUIDE.md`.
  3. The student runs `save_results.sh`, commits `results/` and pushes.
  4. Claude reads `results/` to plan the next step.

```bash

python fpga/gen_fpga_mem.py            # FPGA ROM files after a re-export (--check: is fpga/mem up to date?)
python python/export_frontend.py       # weights/frontend.npz for live words (--verify: 50,000/50,000 identical)
python fpga/kws_live.py --selftest     # board == Python over the USB-UART (--mock: no board needed)
python fpga/kws_live.py --mic          # live words from the PC microphone
python sim/uart_xcheck.py              # Linux + Icarus: kws_live.py packets through the Verilog board design
cd flow/tsmc18 && rc -f syn_int8.g && rc -f fmax_int8.g && innovus -files pnr_int8.tcl   # crosby3
cd flow/tsmc18 && bash results.sh      # INT8 vs INT4 table from the reports
fpga\build.bat nexys4ddr program       # Windows: build (nexys4ddr | nexys4 | nexys_a7_50t), ~25 min, then load it
fpga\program.bat nexys4ddr             # Windows: load results/fpga/kws_fpga_top_<board>.bit again
                                       # (the committed .bit predates the self-check and the UART: build first)
```

Expected results: RTL 0 mismatches on 200 clips (INT8 176/200 correct, INT4 177/200); FPGA BTNU
run-all shows `PASS 176` (INT8) and `PASS 177` (INT4), SW14 fault test `F000 199`;
`kws_live.py --selftest` prints `SELFTEST PASSED`; `sim/uart_xcheck.py` prints `UART CROSS-CHECK PASSED`;
ASIC numbers in `results/RESULTS.md`.

## Problems that were already solved (keep these fixes)

1. **Innovus 20.1 MMMC order** – source the MMMC file *after* `init_design`. With `init_mmmc_file`,
   Innovus reads `slow.lib` before the LEF, keeps 0 cells, and CTS finds no buffers.
2. **No scan flip-flops** – `flow/tsmc18/syn_flow.tcl` sets `avoid` on `SDFF*`/`SEDFF*`; otherwise RC uses
   them as enable flops and Innovus stops placement with IMPSP-9099.
3. **Fmax** – RC area recovery pushes the 100 MHz slack to ~0, so Fmax comes from the separate 2 ns runs
   (`fmax_int*.g`, `kws_fast.sdc`): Fmax = 1 / (2 ns − slack).
4. **FPGA clock** – the LUT ROMs + MAC path is ~17 ns on the Artix-7 (`results/fpga/nexys4ddr/timing_summary.rpt`), so `kws_fpga_top.v` runs at 50 MHz from
   an MMCM (at 100 MHz the route had WNS −4.4 ns). The core needs same-cycle (asynchronous) memory reads, so
   the ROMs must stay distributed; moving them to block RAM needs a core change (see `alt/` for that style).
5. **Paths with spaces** – in Vivado Tcl pass paths to `add_files` inside `[list ...]`; give
   `xsim.simulate.custom_tcl` a relative path; don't pass `-d A=B` to `xvlog.bat` (the batch file splits at `=`).
6. **Vivado from an agent shell** – if Vivado runs fail with "Spawn failed: Broken pipe", remove
   `NoDefaultCurrentDirectoryInExePath` from the environment before starting it (`sim/run_sim.ps1` does this).
7. **FPGA self-check** – BTNU compares every class and all 6 output scores with Python. Vivado fills a ROM
   whose `.mem` file it can't open with zeros (warning `[Synth 8-4445]`), which used to show a false `200 200`.
   Now `Err ----` means the golden-data checksum (`fpga/mem/<p>_check.mem`) failed: the expected, labels,
   logits8 or check file was missing or damaged. A missing weights, biases or inputs file makes every clip fail
   instead (typically `F000   0`). A stale but self-consistent `fpga/mem` still passes BTNU and fails
   `kws_live.py --selftest`; `python fpga/gen_fpga_mem.py --check` catches it before the build.
